# 0030. Discarding a pending key

Status: Accepted (2026-10-01). Amends ADR 0017.

## Context

ADR 0017 allows one pending key per credential. A pending key that is never registered with the Git service, or was
generated by mistake, blocks the next regeneration. The only way out was an emergency replacement, which also replaces
the active key that sync relies on.

## Decision

- `POST /api/v1/admin/credentials/{id}:discard` with `{"keyId": "key_…"}` discards the credential's pending key.
- Like activation, it names the key, and a key that is not the credential's current pending key gives 409. A caller
  cannot discard a key that someone generated after they looked.
- The key becomes `RETIRED`, exactly as on retirement: its five encryption columns are set to null, its public key
  and fingerprint stay. The active key is untouched, and a new regeneration is possible at once.
- It needs `CREDENTIAL_MANAGE` at the root and locks the credential row like every other key change (ADR 0017,
  ADR 0018). A disabled credential refuses it with 409, like the other key changes.

## Consequences

- The API shows a discarded key like any other retired key. The audit events of slice 8 record which operation
  retired a key.
